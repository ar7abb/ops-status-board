# Ops Status Board Backlog

This backlog records possible future improvements without adding them to the approved project scope. An item here is a candidate, not a promise or active task.

## Candidate ideas

### Optional JavaScript frontend

- **Status:** Candidate — not approved or scheduled
- **Idea:** Add a separate JavaScript frontend after the core FastAPI, PostgreSQL, deployment, observability, backup, recovery, and security work is complete.
- **Possible value:** Provide a richer browser interface and demonstrate frontend-to-API integration.
- **Decision gate:** Reassess only after the core project reaches its completion gate. Approving it would require an explicit scope and blueprint update.

## Promotion rule

Before a backlog idea becomes planned work, it must have:

- a clear user or portfolio benefit;
- defined scope and dependencies;
- security, operational, and cost impact reviewed;
- an approved place in the roadmap; and
- an explicit blueprint changelog entry when the approved plan changes.

Until those conditions pass, backlog ideas remain outside the current implementation.
